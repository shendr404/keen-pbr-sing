В keen-pbr-sing страница **Sing-box интерфейсы** описывает прокси как профили. Профиль — это тег outbound keen-pbr, имя TUN-интерфейса и способ выбора узла.

## Профиль

1. Установите sing-box. Отдельный заранее созданный TUN не обязателен: keen-pbr добавляет свой inbound.
2. Откройте **Sing-box интерфейсы**.
3. Задайте тег (например `proxy`), интерфейс (например `sbtun2`), режим и параметры TUN.
4. Сохраните профиль. В keen-pbr появится outbound типа `interface` **без** `gateway`. Для TUN и point-to-point шлюз не нужен, значение `auto` только вызывает предупреждение.
5. В карточке профиля вставьте ссылки, по одной в строке, или подключите подписки.
6. Направьте правило маршрутизации на тег профиля. Несколько таких interface outbound можно объединить в группу `urltest` или `icmptest` на странице Outbounds.

Режимы:

- `direct` — трафик TUN идёт в один выбранный узел.
- `selector` — узел выбирается вручную в карточке профиля. Щелчок по узлу только делает его активным и не меняет режим.
- `urltest` — sing-box выбирает узел по задержке. Укажите URL проверки и интервал. Если в config.json уже включён `experimental.clash_api` на loopback, интерфейс показывает текущий узел. Иначе видно только параметры проверки.

Параметры TUN профиля: стек `gvisor` (по умолчанию) или `system`, MTU (по умолчанию 1400) и адреса. Пустой адрес даёт `172.19.x.1/30`.

## Ссылки и подписки

Поддерживаются `vless://`, `vmess://`, `trojan://`, `shadowsocks`/`ss://` и `hysteria2://` (`hy2://`). Транспорты sing-box 1.14: `tcp`, `ws`, `grpc`, `http`, `httpupgrade`, `quic`. Строки с `xhttp`, `splithttp` и другими неизвестными транспортами пропускаются, остальные узлы сохраняются. В интерфейсе будет предупреждение вида «Пропущено 4 узла: транспорт xhttp не поддерживается sing-box».

Для VLESS Reality без `fp` в TLS добавляется `utls` с отпечатком `chrome`. Параметр `encryption` у VLESS игнорируется: sing-box его не поддерживает.

Подписка может быть текстовым или base64-списком, JSON sing-box или Clash. К одному профилю можно подключить несколько подписок. Интервал задаётся **в часах**; `0` означает только ручное обновление. Демон проверяет срок раз в 30 секунд. Загрузка ограничена 2 МиБ и таймаутом 20 секунд; после неудачи следующая попытка выполняется через пять минут. Ручные узлы сохраняются при обновлении подписки.

Для ручного обновления из SSH:

```sh
/opt/usr/bin/keen-pbr subscriptions refresh --all
# Или отдельный профиль:
/opt/usr/bin/keen-pbr subscriptions refresh <id>
```

Если `sing-box check` не проходит, в ошибке будет строка FATAL/ERROR. Секреты (uuid, пароли, ключи) из неё убираются. Отсутствие бинарника sing-box сообщается отдельно от ошибки конфигурации.

## Что происходит с `/opt/etc/sing-box/config.json`

keen-pbr **не заменяет файл целиком**.

Перед первым изменением существующего файла создаётся одноразовая копия `config.json.bak-keenpbr-original`. Перед каждой следующей записью обновляется только скользящая копия `config.json.bak-keenpbr`. `sing-box check` выполняется до того, как новая версия считается применённой; при ошибке восстанавливается скользящая копия.

Управляемые объекты помечены тегами с префиксом `kpbr-`:

- inbound `kpbr-tun-<id профиля>`;
- исходящие узлы `kpbr-n-…`;
- группа `kpbr-g-<id профиля>` для `selector` и `urltest`;
- запасной outbound `kpbr-direct`, если в файле не было своих outbound.

`dns`, `log`, `experimental` и все остальные inbound, outbound и правила `route` копируются как есть. В том числе смешанный inbound `192.168.1.1:2080`, свой hysteria2 и уже настроенный TUN `sbtun` с адресами IPv4/IPv6, MTU и стеком.

Если интерфейс профиля уже занят чужим inbound (например ручной `sbtun`), сохранение отклоняется и файл не меняется. Выберите другое имя, например `sbtun2`. Так рабочий ручной конфиг, которым пользуется outbound keen-pbr `tun_hu`, не уничтожается при первом сохранении после обновления.

Когда узлов не остаётся, из файла убираются только объекты `kpbr-`. Если кроме них в файле ничего не было, сгенерированный config.json удаляется. Чужие секции остаются, и sing-box перечитывает уже их.

Ссылки профилей лежат в `/opt/etc/keen-pbr/sing-box-links.json` и не попадают в список профилей API.
